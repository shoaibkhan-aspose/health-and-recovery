What runs

Discovery reads every host's robots.txt and every sitemap file (all of them, no sampling). The crawl audit then fetches a sample of pages per URL pattern (template): 2 English pages and 1 page in each of 2 other languages, plus every homepage and family hub, and runs 33 checks on each (2 of them for AI readiness: text visible without JavaScript, structured data). Both only read: GET requests, robots.txt respected, one request per host per second. The speed audit asks Google PageSpeed Insights about the 2 most-visited pages of each template (mobile): Core Web Vitals from real Chrome users over 28 days (75th percentile), plus a Lighthouse lab run that names the biggest savings. Google loads each page once; pages with too few visits have no real-user data and count neither way. The AI audit checks per host whether robots.txt or the firewall blocks AI search crawlers, and whether hosts and product families offer an llms.txt. The text check has an LLM proofread the title, H1 and meta description of every crawl-audit page in its own language, for misspellings, words typed twice, leftover words and a title about a different product; it fetches nothing, and a finding is kept only when the wrong words really appear on the page. On blogs with a source repo, the link check reads every internal link of every post from the repo and checks it on the live site (a target is missing only when the live site answers 404): links into translations that do not exist, damaged links, links to another language although a translation exists, and broken links; it also lists posts missing a supported language. The prioritizer adds Search Console traffic. Manual review findings come from people and are marked until a check confirms them.

Family and host health (A–F)

Scored per product family and per host. A host with families gets its families' health weighted by search clicks, minus the points of host-wide problems that belong to no family. Starts at 100. Each open finding costs broken 40, incorrect 20, not optimized 6 or improvable 2 points, times the share of the family or host it affects (at least a quarter). Findings with one root cause count once, cosmetic issues cost at most 20 in total, and a canonical that points at a missing page counts as broken. A 90+, B 75–89, C 60–74, D 40–59, F below 40. Traffic is not part of health. Where a report shows health by area, each area is scored the same way on its own findings only, so the overall is never higher than an area; speed without real-user data shows no score.

Priority score (0–100)

Search Console clicks on the affected pages over 28 days (impressions count 1% of a click), on a log scale, × severity (broken 1, incorrect 0.7, not optimized 0.4, improvable 0.2) ÷ effort (S 1, M 1.5, L 2.5). If the same pages lost traffic since six months ago, half of that loss counts when it is larger than today's traffic. Hosts without Search Console use GA4 organic sessions.

Samples and estimates

"~N pages affected" applies each template's failing share of the sample to its number of URLs in the sitemaps. Confidence labels say how solid that is; findings marked to confirm rest on one page.

Glossary

Sitemap / sitemap index
An XML file that lists a site's pages for search engines; an index lists other sitemap files.
Canonical
A tag in which a page names its preferred address; Google indexes that address.
hreflang
Tags that link the language versions of a page so Google shows each user the right one; x-default is the fallback.
noindex
A signal that asks search engines to keep a page out of results.
llms.txt
A short Markdown file at /llms.txt that tells AI assistants what a site is and links its key pages; a proposal (llmstxt.org), not a standard.
Structured data (JSON-LD)
Machine-readable facts in a page (what it is, who publishes it) that search and answer engines read.
Redirect (301 / 302)
A URL that forwards to another; 301 is permanent, 302 temporary.
Soft 404
An error page that answers "OK" (HTTP 200) instead of "not found".
Template
A URL pattern shared by many pages of a family, e.g. /cells/conversion/<a>-to-<b>.
Family
A product section of products.aspose.app, e.g. /words/ or /cells/.
Clicks / impressions
Search Console: how often a page was clicked / shown in Google results.
Effort S / M / L
Small: one template or config change. Medium: several templates or translations. Large: rebuild or migration.
