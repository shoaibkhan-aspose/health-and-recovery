      Crawl audit per host
      Speed per subdomain

      Whole host: real Chrome users over 28 days, 75th percentile, mobile (good: LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1). Pages: the most-visited pages per template; "real-user data" counts pages with enough visits for their own numbers. The lab score (Lighthouse, 0-100) varies by up to ~20 points between runs, so it is shown here only, never as a finding.

      AI access per subdomain

      Can AI search and answer engines (ChatGPT search, Perplexity, Claude, Google AI Overviews, Copilot) reach each host? "robots.txt" and "Firewall" test their crawlers; a block there is a finding. Blocks on AI training crawlers (GPTBot, ClaudeBot, CCBot, Google-Extended) are a business choice, shown here only. llms.txt is a proposed convention (llmstxt.org) that some AI tools read: on products, a family counts as covered by its own file or a link from the host's file.

      Health score (0–100)

      health = 100 − Σ weight × share
      SeverityWeight
      Broken40
      Incorrect20
      Not optimized6
      Improvable2
      • share = part of the family or subdomain affected, at least 25%: for sampled checks, ~pages affected ÷ its URLs
      • one root cause counts once; not optimized + improvable cost at most 20 together
      • a subdomain with product families: their scores weighted by clicks, minus subdomain-wide problems
      • traffic is not part of health: a small family's broken pages count as much as a big one's
      • health by area: the same formula on one area's findings, so the overall is never higher than an area; speed without real-user data shows no score
      below 4040–5960–7475–8990+

      Example: a broken finding on 25% of a subdomain costs 40 × 0.25 = 10 points: score 90.

      Reports not yet on the new layout also show a letter: A 90+, B 75–89, C 60–74, D 40–59, F below 40.

      Priority score (0–100)

      score = traffic × severity ÷ effort
      • traffic: Search Console clicks on the affected pages over 28 days, log scale (impressions count 1% of a click)
      • if the same pages lost traffic since six months ago and the loss is larger, half the loss counts
      Severity×Effort÷
      Broken1S: one template or setting1
      Incorrect0.7M: several templates1.5
      Not optimized0.4L: rebuild or migration2.5
      Improvable0.2

      Health says how broken; the score says what to fix first.

      Limits

      • Samples: page checks run on 4 pages per template; "~N pages affected" scales the failing share up to the template's URLs
      • Confidence on each finding: complete, strong, partial or to confirm (one page)
      • Weights (40 / 20 / 6 / 2) are set by judgement, not yet checked against traffic changes
      • Lab speed scores vary by up to 20 points between runs, so they are never a finding
      • LLM findings are reviewed by hand; false positives are removed
      • All audits only read; nothing on any site is changed

      Glossary

      Sitemap / indexXML list of a site's pages for search engines; an index lists other sitemaps
      Redirect 301 / 302a URL forwarding to another; 301 permanent, 302 temporary
      Templatea URL pattern shared by many pages, e.g. /cells/conversion/<a>-to-<b>
      Familya product section of products.aspose.app, e.g. /words/
      Clicks / impressionsSearch Console: how often a page was clicked / shown in Google results
      Core Web VitalsGoogle's page experience metrics from real Chrome users: LCP, INP and CLS (75th percentile, 28 days).
      LCPLargest Contentful Paint: time until the main content is visible. Good ≤ 2.5 s, poor > 4 s.
      INPInteraction to Next Paint: delay between a click or key press and the screen updating. Good ≤ 200 ms, poor > 500 ms.
      CLSCumulative Layout Shift: how much the layout jumps while loading. Good ≤ 0.1, poor > 0.25.
      TTFBTime to First Byte: how long the server takes to start answering. Good ≤ 0.8 s, poor > 1.8 s.
      LighthouseGoogle's lab test that loads a page once in a simulated phone; its score varies between runs.
      hreflangTags linking the language versions of a page, so search shows each user the right one.
      x-defaultThe hreflang fallback for users whose language has no version.
      canonicalThe URL a page declares as its preferred address; search engines index that URL.
      noindexA meta tag or header asking search engines to keep a page out of results.
      H1The page's main heading.
      JSON-LDStructured data in a script tag: machine-readable facts for search and answer engines.
      lastmodThe last-modified date of a URL in a sitemap; crawlers use it to decide what to re-fetch.
      Soft 404An error or empty page that answers HTTP 200 instead of 404.
      llms.txtA Markdown file at /llms.txt describing a site for AI assistants; a proposal (llmstxt.org), not a standard.
      Meta refreshA redirect done by a meta tag in the page instead of an HTTP 301/302.
      viewportThe meta tag that makes a page fit phone screens.
      4xx/5xxHTTP error codes: 4xx = client errors such as 404 not found, 5xx = server errors.
