Site Health Architecture

How the audit runs today, per tenant (aspose.app, conholdate.cloud, aspose.cloud, groupdocs.cloud): seven read-only steps on the Mac collect sitemaps, page checks, AI crawler access, page speed, an LLM proofread of the page text, the internal links of every blog post and search traffic into one findings store per tenant, and every push to GitHub rebuilds the published reports. Dashed parts are planned and not built yet.

Design rules

Checks are code

Status codes, canonicals, hreflang, sitemaps and scores are deterministic and repeatable. LLM agents come in only where judgment is needed: content accuracy, diagnosis, writing fixes. The first LLM step, the text check, only proofreads, and a finding is kept only when its wrong words are on the page.

Read and write are separate

Phase 1 has no write access to any site. Fixers are separate MCP servers with their own credentials, so an audit cannot change a site even by mistake.

One tenant file per property

Nothing in core/ names aspose.app. Hosts, families, URL templates, audit rules and the Google key live in tenants/<tenant>.yaml (aspose.app, conholdate.cloud, aspose.cloud, groupdocs.cloud); each tenant's stores and reports stay in its own data/ and reports/ folder.

Findings are tracked, not re-listed

Each finding keeps one id across runs. A later run that no longer sees it marks it resolved, and it reopens if it comes back. One template fix closes one finding.
